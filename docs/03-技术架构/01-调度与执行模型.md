# 调度与执行模型

更新时间：2026-08-26（Asia/Shanghai）

## 分层

- Store：只保存 definition 与 run。
- Clock：只回答下次到期时间。
- Executor：只执行已经认领的 run。
- Tools / RPC：只调用 service。
- Web client：只展示快照并提交明确 mutation。

## 调度

- `once` / `interval` / `hourly` / `daily` / `weekly` / `monthly` / `custom` 会编译为校验过的 RRULE。
- `interval` 最短 5 分钟，创建后不会立刻跑第一次。
- 每天/每周/每月/自定义间隔天数使用 IANA 本地 `HH:mm`；夏令时中不存在的本地时间会被跳过。
- 立即运行不受计划时间限制。

## 恢复

- 先持久化 `queued`，再创建 Agent。
- Host 重启后，遗留 `queued`/`running` 变为 `failed(host_interrupted)`。
- 补跑窗口默认 15 分钟，只物化最新一条 overdue occurrence。

## 保活

- 运行到终态后不 dispose，而是解除无人值守工具 guard、把审批策略恢复为 `ask`，把句柄交给 service 保活为交互会话。
- 原因：Web 客户端把 `session/disposed` 当作页面生命周期内的永久下线（removed 标记不复位），dispose 会让会话立刻「会话不可用」，只能刷新恢复。
- 上限 `liveSessionLimit`（默认 20），按完成顺序驱逐最旧的空闲会话；正在执行用户回合的会话跳过。`0` 表示跑完立即释放（旧行为）。
- 驱逐/删除/服务关闭释放句柄前会登记 `releasedSessionEvents`，避免 dispose 事件被误判为用户删除。

## 侧栏

- 有 `dsh-codex-ui` 时只填充 `sidebar.schedule`。
- 没有 Codex UI 时不换掉官方任务树，只在外面套「任务 / 定时」页签；官方搜索、工作区和会话菜单都保留。若存在 `sidebar.channels` 再显示「频道」。
- 定时树按任务名称分组，子会话标题为 `YYYY-MM-DD HH:mm - 任务名`。
